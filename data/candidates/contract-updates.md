# RCA contract updates needed for SLM training (Task 4.6)

Task 4.6 found these gaps while building the candidate pool. They concern the `rca-v1` contract (`data/golden/rca-contract.md`, `src/clauseguard/rca/contracts.py`, `src/clauseguard/api/schemas.py`) and must be settled before the Task 4.9 training export. Nothing here changes the contract; each item needs a contract decision.

| # | Change | Reason | Evidence |
|---|---|---|---|
| 1 | **Golden references: hold cause lists, not single strings.** | Golden `source_labels` maps each key to one string. The contract and #53 require source cause lists and multiple-cause references. Candidate references already use `dict[str, list[str]]` plus `causes`, `label_status` and `taxonomy_id`; golden rows and the training export should use the same shape. | `src/clauseguard/datasets/schema.py:308` (`RcaRow.source_labels: dict[NonEmptyStr, NonEmptyStr]`); `src/clauseguard/rca/candidates.py` (`CandidateReference`); `tests/test_rca_candidates.py::test_cause_lists_taxonomies_and_label_states_survive_export` |
| 2 | **Normal operation: define the output for normal windows.** | The contract says normal is "a mapped result when supported; it is not an abstention". But `RcaModelOutput` has only `answered` and `abstained`, and every answered cause must link to a diagnostic claim with incident and specification evidence. The pool holds 18,432 `labelled_normal` TelecomTS windows and 71 BubbleRAN ones. Their targets are undefined until the contract says whether `normal` is a category, what evidence supports it, or whether it is a separate status. | `data/golden/rca-contract.md:35`; `src/clauseguard/api/schemas.py:108-137` |
| 3 | **Label status: keep it out of model outputs.** | An empty cause list cannot distinguish normal, missing labels and abstention. Candidates use `label_status` (`labelled_fault`, `labelled_normal`, `unlabelled`, `ambiguous`) in references only. All SpotLight windows are `ambiguous`. The contract should state that `label_status` is reference metadata and never a target field, and that abstention stays an output state. | `src/clauseguard/rca/candidates.py` (`CandidateReference`); `data/candidates/source-fields.md` (SpotLight) |
| 4 | **Settings evidence: add an evidence type.** | TeleLogs supplies engineering parameters (tilt, azimuth, beam scenario, height). `KpiStatisticEvidence.value` must be a finite float, so categorical settings cannot be represented, and `ModalityState` has no settings modality. Candidates record a `settings` state outside the packet until a type exists. | `src/clauseguard/rca/contracts.py:11,47`; `rca/candidates.py` (`ModalityStates.settings`) |
| 5 | **Packet prediction head: fix it in the contract.** | `rca-v1` packets carry one `detector_prediction`. Task 4.4 packets use the **diagnosis** head. The Step 9 draft proposes the **category** head. Candidates default to diagnosis (`CandidateConfig.packet_head`) and store all three heads by reference. | `src/clauseguard/cli/build_evidence.py:32`; `CandidateConfig.packet_head` |
| 6 | **`final_fault_categories`: tie categories to a taxonomy.** | `RcaCauseOutput.category` is free text. With several source taxonomies (`telecomts-v1`, `bubbleran-pi-v1`, `spotlight-v1`, `telelogs-v1`), a target category needs a declared taxonomy, or a reviewed cross-source mapping, so it can be checked against references. Multiple causes need one diagnostic claim each, as the output validator already requires. | `src/clauseguard/api/schemas.py:101-137`; `data/golden/rca-contract.md:37-49` |
| 7 | **`reuse_terms`: fill it in packets.** | `SourceIdentity.reuse_terms` exists, but the adapters leave it `null` in every packet. The candidate inventory now records licence, redistribution and training use per source and could fill it. | `src/clauseguard/rca/contracts.py:23`; `inventory.json` in a candidate release |
| 8 | **Baselines: decide on a fixed rule.** | No verified baseline exists, so targets cannot make change claims. A fixed within-window rule (`window_first_half` in `rca/evidence.py`) fails when a fault starts at sample 0, which is common in TelecomTS anomaly bounds. The contract should state whether such a rule may be used for training packets. | `src/clauseguard/rca/evidence.py` (`BASELINE_RULES`, `attach_baseline`) |
